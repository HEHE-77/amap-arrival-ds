# 到达页意图识别规则

到达页按「意图维度」决定出哪些模块、按什么顺序、用什么标题和内容。规则来源是《高德到达页信息优先级模拟器 v17.2》，之后的调整都记在这里。代码实现在 `app/intent.js`（维度、`layout()` 编排、各模块数据），模拟器页面 `app/index.html` 只展示选项，不再写说明文字。

## 典型场景

典型场景只是一组预设参数，套用后每个维度都能单独改；改到和预设不一致时，典型场景变为未选中。

| 典型场景 | 片区 | Figma 整页 | 预设：出行 / 到访 / 常驻 / 终点 / 时段 / 收藏 |
|---|---|---|---|
| 本地人开车去商场 | 商场 · 消费 | `812:7852` | 自驾 / 2–3 次 / 常驻城市内 / 商场 / 饭点 / 无收藏 |
| 外地游客到景区 | 景区 · 体验 | `812:7853` | 公交地铁 / 0–1 次 / 非常驻 / 景区 / 平时 / 有收藏 |
| 上班族打车到公司 | 写字楼 · 通勤 | `812:7854` | 打车 / ≥4 次 / 常驻城市内 / 写字楼 / 早高峰 / 无收藏 |

## 意图维度

| 维度 | 选项 | 决定什么 |
|---|---|---|
| L1 出行方式 | 自驾 · 骑行 / 步行 · 公交地铁 · 打车 | 打车付款卡、末班车、周边服务工具条首项、驾车服务 |
| L2 到访频次 | 0–1 次（首次到访）· 2–3 次（偶尔来）· ≥4 次（常去地点） | 近 90 天该 1km 网格的到访次数；决定附近精选的榜单顺序与「上次那杯」；写字楼 0–3 次按访客处理 |
| L2 常驻城市 | 非常驻城市 · 常驻城市内 | 当地特色菜、酒店榜、附近精选首张前置、异地限行 |
| L3 终点类型 | 商场（AOI）· 景区（AOI）· 写字楼（AOI）· 餐饮单店（POI） | 商场 / 景区 / 写字楼为 AOI 片区，决定页头、扫街榜、周边推荐；餐饮单店为 POI，沿用当前片区 |
| L3 到店状态 | 正常营业 · 排队 90 分钟 · 今日已打烊 | 仅餐饮单店；决定扫街榜 TOP 3 是否被唤起 |
| L4 时段 | 早高峰 8:14 · 饭点 12:30 · 平时 15:20 · 21 点后 21:40 | 单店换店、TOP 3 标题、还能待多久、末班车、通勤时间线；已关门的地点不推荐 |
| L5 收藏 | 附近无我的收藏 · 我收藏过的店就在附近 | 命中时出「你的收藏就在附近」，位于驾车服务之前；首次到达时提到扫街榜 TOP 3 之后 |

## 页面编排

所有场景顶部固定为：周边服务 →（打车）打车付款 →（餐饮单店）到达商家卡 →（21 点后乘公交地铁）今晚末班车。底部固定为：（非 21 点的公交地铁）今晚末班车 →（有收藏）你的收藏就在附近 →（自驾）驾车服务。首次到达（0–1 次）且有收藏时，「你的收藏就在附近」提到扫街榜 TOP 3 之后（餐饮单店没有扫街榜时跟在商家卡之后）：对这里不熟，收藏的店是最确定的去处。

中间的推荐模块按场景：

| 场景 | 推荐模块顺序 |
|---|---|
| 商场 | 扫街榜 →（外地）当地特色菜 → 附近精选 → 还能待多久 |
| 景区 | 扫街榜 → 附近精选 →（外地）当地特色菜 → 还能待多久 |
| 写字楼 | 见下方「写字楼」 |
| 餐饮单店 | （排队 / 打烊时）扫街榜 → 还能待多久 → 附近精选 |

没有内容的模块（比如全部关门）整块不出现。

## 模块规则

### 扫街榜 TOP 3
- 标题：餐饮单店「猜你想吃」；写字楼 ≥4 次「中贸商圈」，0–3 次早高峰 / 饭点「猜你想吃」、其他「猜你想去」；商场按吃 / 逛分「猜你想吃」「猜你想逛」；景区「猜你想去」。
- 主按钮：餐饮看团购、景点订门票、咖啡早餐一键下单、零售看优惠；写字楼 ≥4 次首卡为「上次那杯」。

### 附近精选
- 固定 3 张榜单卡。先按场景 × 到访频次的顺序排；外地人首张按时段前置（早高峰烟火小店、饭点本地人爱去、平时下午茶、21 点后酒店）并补酒店榜。
- 不足 3 张时依次补其他榜单；餐饮单店先补非餐饮，再补餐饮。
- 景区场景附近精选紧跟扫街榜。

### 写字楼：访客与上班族
到访 0–3 次（首次到 / 偶尔来，不分本地外地）多是来开会、面试、拜访，按访客处理；≥4 次按上班族。

| | 访客（0–3 次） | 上班族（≥4 次） |
|---|---|---|
| 周边服务 | 打印复印、ATM 排最前，快递柜放最后 | 便利店、快递柜、电梯口…… |
| 早高峰 / 平时的歇脚模块 | 到早了先坐会儿 | 工作休息出来走走 |
| 早高峰 / 饭点的推荐 | 附近精选（按到达时刻判断营业） | 午休去哪儿（按 12:00 判断营业） |
| 之后去哪 | 忙完去哪儿（大唐不夜城、易俗社、长安书院） | 下班好去处（健身房、易俗社、长安书院；按 18:30 判断营业） |

- 21 点后不分访客、上班族，统一叫「附近好去处」，按到达时刻判断营业。
- 外地 + ≥4 次 + 饭点：「吃腻了换换口味」排在第一张。
- 推荐顺序：早高峰 扫街榜 → 歇脚 → 推荐 → 之后去哪；饭点 扫街榜 → 推荐 → 之后去哪；平时 扫街榜 → 歇脚 → 之后去哪；21 点后 扫街榜 → 附近好去处。
- 当地特色菜（仅外地人）至少排在第 3 个推荐模块（扫街榜算第 1 个，按实际显示的模块计）；平时放到所有推荐之后。

### 餐饮单店
- 按时段换店：早高峰麦当劳（早餐一键下单，展示两条团购、不显示热评）、饭点胡大饭馆、平时满记甜品、21 点后木屋烧烤；分店名与地址随片区变化。
- 打车到达时，付款卡终点与页头跟随这家店。

### 营业时间
- 到达时已关门或还没开门的地点不推荐（`HOURS` 表；未登记的视为营业）。
- 面向之后时段的模块按那个时刻判断：午休去哪儿 12:00、下班好去处 18:30；访客的附近精选、21 点后的附近好去处按到达时刻。

### 末班车
- 仅公交地铁、非早高峰出现。21 点后排在到达对象（打车付款卡 / 商家卡）之后、所有推荐之前；其他时段在推荐之后。

## 待确认
- 数据端：专程前往的指标为人数 + 累计导航公里数。
- 付款卡：Figma 图 9 终点写的是「壹号大院（南门）」，与通勤场景的「中贸广场 B 座」不一致，模拟器按场景用中贸广场 B 座（南门）。
- 末班车位置：21 点后提到推荐之前是模拟器的判断，高保真中未给出位置。
- 到店受阻提示条（排队 / 打烊）在 Figma 中暂无设计，当前为暂定样式。
- 店名之外的价格、菜品、营业时间、分店地址、车费、已售数量为模拟数据。
